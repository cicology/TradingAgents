## Current Gate

**Phase 0 — Lock and baseline: E0 verified 2026-09-03 (commit range `3b39fac`..`9aca5e2`).**

Phase 0 is complete when the offline test suite passes and no public CLI path can submit a live order. As of TA-001–TA-009, all nine E0 exit-criteria items are met: live execution is unreachable (paper-only gate in `operating_mode.py`, independently enforced in the Node bridge); every sizing route (MT5 lots, Binance quantity) is deterministic and shared; the risk agent's declared cap and the desk's own Kelly cap both bound size, with the tighter one always winning; a missing or wrong-side stop fails closed instead of routing with `sl=0`; minimum-volume rounding is floor-only and rejects rather than inflates; a failed `order_check()` no longer records a paper position open; `record_close()` has an operator-facing caller and shared risk state is written atomically; the full offline suite (57 tests) passes; root CI runs it on every push/PR; and the operator/verification runbook (`docs/RUNBOOK.md`) is current.

**Phase 1 — Data, models, and ledger: E1 verified 2026-09-03 (TA-101–TA-106).** Canonical domain models (`domain.py`), a durable SQLite ledger with append-only lifecycle/safety/decision/outcome tables enforced by DB triggers (`ledger.py`), a strict decision validator (`validation.py`), and confidence-free deterministic sizing (`sizing.py`). `risk.record_open()`/`record_close()` write immutable lifecycle events for both legacy venues. E1's "reproducible run" bar, initially left open pending an actual producer, is now met by Phase 2's `run_slice()` (TA-206) exercising this infrastructure end to end — see below.

**Phase 2 — XAU/USD vertical slice: complete 2026-09-03 (TA-201–TA-206).** `market_data.py` ingests closed 15m/1h MT5 bars (never the forming bar); `evidence.py` hashes them deterministically; `strategy.py` runs a versioned, LLM-free EMA-crossover strategy; `paper_broker.py` sizes and fills with explicit spread/slippage/commission; `lifecycle.py` replays stop/target/expiry conservatively (worst-case intrabar resolution); `outcome_report.py` exports operator-readable, ledger-matching totals. `run_slice.py::run_slice()` (TA-206, added mid-phase once TA-201–205 existed as separate pieces but nothing tied them together) runs the complete loop in one reproducible, idempotent call and is what closes E1's "reproducible run" gap. **Scope note:** the legacy CLI (`cli.py`, `pipeline.py`) still runs the Phase-0-hardened Kelly-based path for its own analysis flow — `run_slice()` is a new, separate entry point, not yet wired into `desk` CLI subcommands or a live MT5 data feed (bars are caller-supplied `Bar` lists in every test). CLI wiring and a scheduled run are Phase 5 (TA-501) territory, not required for this gate.

The [productization readiness assessment](productization/PRODUCTIZATION_READINESS_2026-09-03.md) currently rates the invite-only paper beta at **18% ready**. Public paid research is **10% ready** and customer-facing live automation is **5% ready**. These scores are planning estimates, not test coverage.
